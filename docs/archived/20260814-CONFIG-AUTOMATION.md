# 配置自动化方案（细化版）

目标：让 MATEa 的配置从「填表」变成「向导」，从「70 个字段」变成「15 行 + 点几下」，同时成为后续用户体验的基础保障。

---

## 核心理念

**YAML 只做一件事：启动服务。** 其余所有配置都应该在 Web UI 里完成，且尽可能自动检测。

**配置来源优先级（运行时）**：

```
数据库覆盖 > YAML 文件 > 代码默认值
```

- 向导和 SystemConfig 页面写入 `system_config` 表；
- 删除 DB 中的 key 后自动回退到 YAML；
- 因此 `config.yaml` 适合作为「基线/默认值」，而 DB 是「运行时覆盖」。

---

## 一、first-run 体验（零配置启动）

当前 `WriteBootstrapConfig` 已经生成最小配置，但用户拿到后仍不知道下一步干嘛。改进后：

```
$ ./matea

  ╔══════════════════════════════════════════╗
  ║   MATEa 已启动                           ║
  ║                                          ║
  ║   首次使用？请先完成初始化：              ║
  ║   → http://localhost:8080/setup          ║
  ║                                          ║
  ║   Setup Token:  abc123-def456-ghi789     ║
  ║   （30 分钟内有效，仅限本机/首次启动）    ║
  ║                                          ║
  ║   已有配置？直接访问：                    ║
  ║   → http://localhost:8080                ║
  ╚══════════════════════════════════════════╝
```

`/setup` 页面是一个全屏向导：

- **未初始化且处于 Setup Token 时间窗内**：无需登录即可访问；
- **已初始化或窗口已关闭**：自动跳转到登录页；
- 首次初始化完成后，强制要求修改默认管理员密码（不可跳过）。

### Setup Token 安全模型

- 首次启动时生成一次性随机 token，打印在控制台；
- 有效期 30 分钟，仅允许使用一次；
- 与 `auth.default_admin_password` 解耦：即使默认密码泄露，没有 setup token 也无法通过向导重置；
- 窗口关闭后如需再次进入向导，必须由已登录 admin 手动触发「重新初始化」。

## 二、Web UI 配置向导（三步走）

### 第一步：Gitea 连接

| 字段 | 输入方式 | 说明 |
|------|---------|------|
| Gitea 地址 | 文本框，占位 `http://localhost:3000` | 必填 |
| 管理员 Token | 密码框 | 必填，自动测试连接并检查 scope |
| Webhook 密钥 | 密码框 | **可选，留空则自动生成**；后续显示在「Webhook 设置」提示中 |
| 自动创建 Agent 账号 | 开关 | 默认开启，对应 `gitea.auto_provision` |

**自动检测/验证**：点击「测试连接」后，后端：

1. 调用 `GET /api/v1/version` 验证 Token 有效性；
2. 调用 `GET /api/v1/user` 检查 Token 所属用户及权限 scope；
3. 确认 Token 至少包含 `write:admin` + `repo` 权限；
4. 获取 Gitea 版本号返回前端；
5. 如 `webhook_secret` 为空，生成 32 字节随机 hex 并暂存（仅完成向导时写入 DB）。

**站点级 Webhook 提示**：向导不自动注册仓库级 webhook（因为不知道目标仓库），但在完成页提供：

```
站点管理 → Webhooks → 添加 Webhook（Gitea）
目标 URL: http://<matea-host>:8080/webhook/gitea
密钥: <auto-generated-secret>
事件: Issues / Issue 评论 / Pull Request / PR 评论
```

### 第二步：LLM 配置

#### 2.1 Provider 预设模板

| 提供商 | 自动填充 | 用户只需填写 |
|---|---|---|
| DeepSeek | `base_url=https://api.deepseek.com/v1`, 默认模型 `deepseek-v4-flash` | API Key |
| OpenAI | `base_url=https://api.openai.com/v1`, 默认模型 `gpt-4o` | API Key |
| Anthropic | `base_url=https://api.anthropic.com/v1`, 默认模型 `claude-sonnet-4-20250514` | API Key |
| SenseNova | `base_url=https://token.sensenova.cn/v1`, 默认模型 `deepseek-v4-flash` | API Key |
| Ollama | `base_url=http://localhost:11434/v1`，自动拉取模型列表 | 无需 Key（本地） |
| 自定义 | 空 | Base URL + API Key + 模型 |

#### 2.2 本地服务自动检测

启动时/进入配置页时扫描以下地址：

| 服务 | 检测地址 | 命中后行为 |
|---|---|---|
| Ollama | `http://localhost:11434/api/tags` | 自动填入 base_url 并拉取模型列表 |
| OpenCode | `http://localhost:4096/health`（或用户指定端口） | 提示「检测到 OpenCode，可在 Hub 后端配置中接入」 |
| 其他 Hub | `http://localhost:9090/health` 等 | 仅作为常见端口提示，不自动填充 |

> 注意：OpenCode 没有官方固定端口，向导应允许用户输入端口后再检测，而非只扫描单一端口。

#### 2.3 Hub 后端配置（进阶，默认折叠）

Phase 2 新增的 `agents.backends`（`hub-opencode` / `hub-hermes`）不在当前 `configKeys` 白名单内，需要：

- 在 `ConfigManager` 中新增对 `agents.backends` 的 CRUD 支持；
- 或把 Hub 后端拆分为独立资源（命名后端，可被多个 Agent 引用），更接近产品设计；
- 向导中默认折叠，仅当用户明确选择「我要用 OpenCode/Hermes 作为编码后端」时展开。

### 第三步：确认

展示配置摘要（敏感字段 mask）：

```
Gitea 地址:    http://localhost:3000  ✅ 已连接
Agent 账号:    自动创建              ✅
Webhook 密钥:  ••••••••              ✅ 已生成
默认 LLM:      deepseek (deepseek-v4-flash)
Hub 后端:      未配置（可在系统配置中后续添加）
```

点击「完成」后：

1. 批量写入 `system_config` 表（Gitea/LLM/Webhook/Auth 等）；
2. 调用 `onConfigChange` 热重启相关组件（LLM Registry、Gitea Client、Dispatcher）；
3. 标记初始化完成，关闭 setup token 窗口；
4. 跳转至强制修改默认管理员密码页；
5. 密码修改成功后进入仪表盘。

## 三、YAML 配置精简

### 当前 `config.example.yaml`（49 行）→ 精简后（~15 行）

```yaml
# config.yaml — 启动配置，其余全部在 Web UI 中完成
# 首次运行无需此文件，会自动生成并进入向导

server:
  host: "0.0.0.0"
  port: 8080

database:
  path: "./data/matea.db"

# 以下可选，留空则通过 Web UI 配置
# 推荐用环境变量注入敏感信息
gitea:
  url: "${GITEA_URL:-}"
  admin_token: "${GITEA_ADMIN_TOKEN:-}"

llm:
  provider: "${LLM_PROVIDER:-}"
  api_key: "${LLM_API_KEY:-}"

auth:
  jwt_secret: "${JWT_SECRET:-}"         # 留空则首次启动自动生成
  default_admin_password: "${ADMIN_PASSWORD:-}"  # 留空则首次启动自动生成并打印
```

### 删除的字段及其去向

| 删除字段 | 去向 |
|---------|------|
| `gitea.webhook_secret` | Web UI 配置，留空自动生成 |
| `gitea.auto_provision` | 默认 true，Web UI 可选关闭 |
| `workspace.*` | 全部自动（`./data/work`），Web UI 可改 |
| `dispatcher.*` | 全部自动（`max_concurrent: 2` 等），Web UI 可改 |
| `logging.path` | 固定 `./data/logs`，不配 |
| `llm.providers.*` | Web UI 配置，支持多 Provider |
| `llm.defaults.*` | Web UI 配置 |
| `llm.rate_limit_retries` | 默认 1，不配 |
| `debug.*` | 默认关闭，不配 |
| `deliver.*` | Web UI 配置，留空关闭 |
| 所有 `agents.*` | Web UI 配置（其中 `agents.backends` 需新增支持） |
| 所有 `workflow.*` | Web UI 配置 |

## 四、自动检测能力矩阵

| 检测项 | 时机 | 实现方式 | 优先级 |
|--------|------|---------|--------|
| 本地 Ollama | 启动时 + 配置页 | `GET http://localhost:11434/api/tags` | P0 |
| 本地 OpenCode | 启动时 + 配置页 | `GET http://<host>:<port>/health`（端口可配置） | P0 |
| 本地 Hermes | 启动时 + 配置页 | `GET http://<host>:<port>/health`（端口可配置） | P1 |
| Gitea 版本 | 配置页测试连接 | `GET /api/v1/version` | P0 |
| Gitea Token Scope | 配置页测试连接 | `GET /api/v1/user` 解析权限 | P0 |
| 站点级 Webhook 状态 | 完成向导时 | `GET /api/v1/admin/hooks` 检查目标 URL 是否存在 | P1 |
| 可用模型列表 | 配置页测试 LLM | `GET /models` 或 `/api/tags` | P1 |
| 文件系统可用空间 | 启动时 | `statfs` 检查 `data/` 所在分区 | P2 |

## 七、设计原则

1. **YAML 是保险丝，不是控制台**——只做启动，不做日常管理。
2. **能自动的绝不手动**——检测到 Ollama 就直接填好，让用户点确认。
3. **能默认的绝不配置**——`max_concurrent: 2`、`workspace: ./data/work` 这种，用户不问就不露。
4. **向导只说人话**——不说「JWT Secret」，说「安全密钥，自动生成」。
5. **高级配置不消失，只是藏起来**——SystemConfig 页面保留全部字段，但引导页只露最必要的。
6. **安全优先**——setup token、强制改密、敏感字段 mask、配置变更审计是底线。
7. **可回退**——DB 覆盖可随时删除，回退到 YAML 默认值。
