## 四、亮点与注意

### 亮点
1. **迁移纪律好**：纯机械提交独立可构建，`giteaingress` 别名一次性规避包名冲突，无二次返工。
2. **崩溃重放契约显式保持**：`ParseIntent` 在 live 与 `ReplayAccepted` 两条路径共用，注释明确点名"live 和 replay 产出一致"——这是 P1 已建能力的延续，未因重构退化。
3. **JSON 契约测试覆盖到位**：`Event json:"-"` 防泄露、`omitempty`、预留字段往返三件套都在，为 Phase 2 MCP/API/CLI 接入立了可验证基线。
4. **零行为变更可信**：resolver 实际 diff 证明仅为别名，路由语义未动。

### 注意（非阻塞）
1. **工作树侧记**：`git status` 显示 `.claude/settings.json` 有未提交改动（`M`），**与 Phase 1.3 无关**，疑为本地配置调整，提交前请留意别误带。
2. **`WrapEvent` 按引用**：`TestWrapEvent` 已用 `assert.Same` 钉死"无拷贝"语义。这是有意的——dispatcher 侧若对 `evt` 做 mutation 会反映到原对象。当前 dispatcher 不 mutate 输入，但 Phase 2 接 MCP 生产者时需记得此契约（JSON 反序列化路径不受影响，仅 `WrapEvent` 路径需注意）。
3. **Intent 当前是薄封装**：`Event` 仍直接持有 `*WebhookEvent`，Phase 2 多源接入时 `Intent` 可能需要更结构化的 `Payload any` 或源特定子结构；建议届时在 Intent 上直接演进，不要再用 `WebhookEvent` 承载非 Gitea 源。
4. **验证边界**：本沙箱跑全 15 包完整套件会被命令超时中断（慢速 git 集成测试单条 56s）。已定向覆盖**全部新增代码路径** + build + vet + 关键集成路径，均通过；建议 CI 跑全量做最终确认。
